# Методология индекса

## Задача

Для каждой H3-ячейки (res 9, средняя площадь ≈ 0.105 км²) и каждого типа
бизнеса нужно ответить: насколько локация привлекательна для открытия точки.

Индекс — эвристика приоритизации. Он не заменяет P&L-модель, но позволяет
сузить сотни ячеек до короткого списка для поля.

## Признаки

Считаются в радиусе `radius_m` (по умолчанию 500 м) вокруг центра ячейки:

| Признак | Смысл |
|---------|-------|
| `new_buildings` | здания с `completion_year >= current_year − 5` |
| `new_residential_units` | квартиры в новостройках (факт или эвристика `levels × 4`) |
| `residential_units` | все квартиры в радиусе |
| `population` | `residential_units × 2.2` (допущение) |
| `competitor_count` | POI из `competitor_categories` бизнеса |
| `competitor_density_km2` | конкуренты / площадь круга |
| `transport_stops` | остановки автобуса/трамвая/метро/жд |
| `poi_diversity` | число различных категорий POI |
| `building_count` | здания в радиусе (фильтр пустых ячеек) |

Категории конкурентов:

- кофейня: `coffee`, `cafe`, `bakery`;
- ПВЗ: `parcel_locker`, `post_office`.

## Нормировка

Каждый признак переводится в 0…1 по городу:

```text
norm(x) = clamp((x − min(x)) / (max(x) − min(x)), 0, 1)
```

Python-версия использует `p95` вместо `max`, чтобы один выброс не «схлопывал»
остальные значения. dbt-версия использует min/max — расхождение допустимо и
описано в модели. Для маленьких городов, где все значения равны, нормировка
возвращает 0.

## Компоненты

```text
demand      = 0.50 × norm(new_residential_units)
            + 0.30 × norm(new_buildings)
            + 0.20 × norm(population)

access      = norm(transport_stops)
diversity   = norm(poi_diversity)
competition = norm(competitor_count)
```

`demand` отвечает на вопрос «есть ли рядом люди и новые жилые массивы»,
`access` — насколько легко туда добраться, `diversity` — насколько локация
«живая», `competition` — насколько рынок занят.

## Индекс

```text
index = 100 × (
    w_demand × demand
  + w_access × access
  + w_diversity × diversity
  + w_competition × (1 − competition)
)
```

Веса задаются в `config/business_types.json`:

| Бизнес | demand | access | diversity | competition |
|--------|-------:|-------:|----------:|------------:|
| Кофейня | 0.45 | 0.20 | 0.10 | 0.25 |
| ПВЗ | 0.50 | 0.15 | 0.10 | 0.25 |

`1 − competition` — штраф: чем больше конкурентов, тем ниже итог при прочих
равных. Именно это operationalizes гипотезу «новостройки без конкурентов».

## Уверенность

`confidence` ∈ [0, 1] растёт с числом объектов в радиусе:

```text
data_points = 2×building_count + poi_count + 3×transport_stops
confidence = min(1, 0.35 + 0.65 × min(1, data_points / 80))
```

Низкий confidence — сигнал, что данные OSM неполные и ячейку нужно проверить
вручную.

## Рекомендации

| Индекс | Код | Действие |
|--------|-----|----------|
| ≥ 70 | A | открывать / ехать на поле |
| 55–70 | B | рассмотреть, нужна проверка |
| 40–55 | C | наблюдать |
| < 40 | D | не рекомендуется |

## Проверка гипотезы

1. Для ячеек с известным `observed_revenue_growth_pct` считаются квартили по
   индексу.
2. Сравнивается средний рост выручки в верхнем и нижнем квартилях (`uplift_pp`).
3. Считается Spearman ρ между индексом и ростом (без scipy/numpy).
4. Статусы: `supported_on_synthetic_data`, `weak_signal`, `not_supported`,
   `not_enough_data`.

В демо `observed_revenue_growth_pct` генерируется из латентных драйверов
(новые квартиры, конкуренты, транспорт, разнообразие) плюс шум. Поэтому uplift
на демо показывает, что пайплайн и валидация работают, **но не является
доказательством гипотезы**. Для реальной проверки:

- подключить выручку/чеки по точкам или агрегированный рост по сетке;
- контролировать возраст точки, формат, бренд, этаж, пешеходный трафик;
- использовать holdout по времени и минимум 2–3 города;
- считать доверительные интервалы и проверять устойчивость к весам.

## Что важно для интерпретации

- 500 м — евклидов радиус, а не пешеходная доступность. Для точности нужны
  isochrones.
- OSM-полнота неравномерна: в новых районах POI может быть меньше не потому,
  что их нет, а потому что их не нанесли.
- Год постройки и число квартир часто отсутствуют; эвристика `levels × 4`
  систематически ошибается для нестандартных домов.
- Индекс чувствителен к весам. В проде их стоит калибровать на исторических
  открытиях/закрытиях и revenue-данных.
